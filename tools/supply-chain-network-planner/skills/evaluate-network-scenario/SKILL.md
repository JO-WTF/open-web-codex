# 评估仓网方案

1. 先确认 Case 的 `normalized_input` 和 `route_matrix` 已就绪；成本问题还要求 `cost_matrix` 就绪。
2. 明确计算目标：时效问题默认要求用户确认 `min_time`，成本问题使用 `min_cost`。不能用一个目标下的覆盖关系冒充另一个目标下的结果。
3. 当前覆盖存在时按原关系评估，不重新分配；缺失时明确使用现有仓优化基线。
4. 增仓、关仓或搬仓只能引用 Case 中已有仓或候选仓。固定已有仓默认不能关闭，除非用户明确把它设为可选。
5. 基线和方案必须使用相同的数据版本、矩阵方法、成本规则和时效目标，之后才能比较。

输出需求加权覆盖率、总成本、分仓成本、仓库变化和方案标签。所有明细保存在 Case；消息中只给有限摘要。方案模拟不是对任意地理位置的全局最优证明。
