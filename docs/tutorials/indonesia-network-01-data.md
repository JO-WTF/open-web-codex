# 认识要上传的数据

仓网分析不要求固定文件名或固定表头，但需要知道每份数据在业务上代表什么。最简单的做法是把下表中的信息分别放在一张或多张表里上传。

| 数据 | 用途 | 至少要能说明什么 |
| --- | --- | --- |
| 需求城市 | 计算要服务的需求 | 城市、需求量、位置或可匹配的行政区 |
| 现有仓库 | 评估现在可以从哪里发货 | 仓库、仓库类型、所在城市或坐标 |
| 候选仓库 | 评估新增仓或自动选址 | 候选地点和所在城市或坐标 |
| 路线或报价 | 计算时效和成本 | 起点、终点、运输时间或距离；有成本时还需报价单位 |
| 行政区目录 | 补充或核对城市位置 | 城市与经纬度的对应关系 |

人口、销量快照等辅助文件可以一起上传，但不会因为它们缺少仓库字段而阻塞你的任务。

## 表头不一样，也能用

下面三种表头都可能表达“需求量”：

```text
demand_quantity
Demand Qty
月均发货量
```

系统会结合表中其他字段和样本值判断含义。Excel 的不同 sheet、JSON 的不同数组也会分别看待。

只有下面这些情况才会出现输入卡片：

- 两个字段都像需求量，但含义不同；
- 数值没有单位，且单位会改变计算结果；
- 仓库究竟是中心仓还是越库仓（XD）无法判断；
- 同一城市或仓库编号有互相冲突的内容；
- 选中的记录真的缺少分析不可少的值。

回答卡片后，继续等待原任务即可。不要为了改一个表头就删除文件重传，除非你确认原文件本身有误。

## 示例数据包含什么

[印尼示例目录](../../apps/web/scripts/fixtures/warehouse-network/mock_data/)包含：

- `demand-cities.csv`：城市需求；
- `existing-warehouses.csv`：现有中心仓和越库仓；
- `candidate-warehouses.csv`：可供选择的新增仓；
- `route-quotes.csv`：路线、时长和报价；
- `administrative-areas.json`：城市位置目录；
- `population-snapshot.csv`：需求的辅助核对数据。

示例中的 `manifest.json` 只是文件清单，不用上传。

## 数据准备完成后会发生什么

系统会把本次选中的数据整理成一份分析输入，保留来源和字段对应关系。原始文件不会被覆盖。只要你没有修改选中的来源，后续追问会继续使用这份已准备的数据；改了数据后，系统会重新检查，而不会拿旧结果冒充新结果。
