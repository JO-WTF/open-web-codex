# 10 分钟跑通完整仓网示例

这次练习会得到三张地图和三个可直接讨论的结论：现有仓网的 12 小时时效、增加 Balikpapan 仓的影响，以及达到 90% 目标所需的最少新增仓。

示例数据是合成的印尼城市和仓库数据，只用于学习流程，不代表真实商业结论。

## 1. 上传示例数据

创建一个新的 Workspace，上传[示例目录](../../apps/web/scripts/fixtures/warehouse-network/mock_data/)中的六个数据文件：

```text
administrative-areas.json
candidate-warehouses.csv
demand-cities.csv
existing-warehouses.csv
population-snapshot.csv
route-quotes.csv
```

不要上传 `manifest.json`；它只是示例文件清单，不是计算数据。

如果你使用自己的数据，文件名和表头可以不同。详情见[认识要上传的数据](indonesia-network-01-data.md)。

## 2. 创建任务

1. 在这个 Workspace 中点击 **New task**。
2. 选择 **Warehouse Network · Multi-Agent**。
3. 发送下面这句话：

   ```text
   根据我上传的文件计算 12 小时时效达标率并绘制地图。
   ```

等待任务完成。首次处理会检查文件和计算路线，所以比后续追问花的时间更长。

## 3. 查看第一份结论

完成后，应看到：

- 12 小时的需求量加权达标率；
- 城市达标率；
- 达标和未达标城市分开的地图；
- 对本次计算范围和限制的简短说明。

不要只看一条服务线路判断好坏。用地图的城市颜色和结果中的两个达标率一起判断。

## 4. 在同一个任务里评估 Balikpapan

继续发送：

```text
评估添加仓库 Balikpapan 之后对时效达标率的影响，并绘制对比地图。
```

如果出现输入卡片，选择第一个默认选项即可继续本示例。完成后重点看“从多少提升到多少”和“增加了多少个百分点”，以及哪些城市由新增仓改善。

## 5. 找出最少新增仓

继续发送：

```text
计算时效达标率为 90% 的前提下最少的新增仓库数量和选址结果，并用地图可视化。
```

完成后，应拿到：

- 需要新增的仓库数量；
- 被选中的仓库列表；
- 最终能达到的时效达标率；
- 显示仓库和城市覆盖情况的地图。

如果当前候选仓无法达到 90%，系统会明确告诉你“无法达到”，而不会给出看似成功的方案。

## 6. 想用单 Agent 再跑一次？

在另一个新任务中选择 **Warehouse Network · Single Agent**，上传相同文件，发送相同的三句话。它没有额外的专业角色，但同样会先检查数据、完成计算并展示地图。不要在同一个任务中比较两种模式的内部过程；业务上只需要比较最终结果是否满足你的目标。
